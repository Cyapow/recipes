# Recipes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private household recipe book at `https://recipes.matchapman.dev` with AI describe-to-recipe, URL import, a keep-screen-on cooking view, and nightly Google Drive backup.

**Architecture:** One Node/TypeScript container: a Fastify API plus a React/Vite PWA served as static files. SQLite (`/data/recipes.sqlite`) and images (`/data/images/`) live on one volume. AI and Google Drive sit behind small interfaces (`AiClient`, `DriveClient`) so everything is testable with fakes.

**Tech Stack:** Node 22, TypeScript, Fastify, better-sqlite3, zod, vitest, React + Vite + react-router-dom, @anthropic-ai/sdk, google-auth-library, cheerio, sharp, Docker Compose, Caddy (existing shared instance).

**Spec:** `docs/superpowers/specs/2026-10-25-recipes-design.md`

## Global Constraints

- Public URL `https://recipes.matchapman.dev`, home wifi only, no login. HTTPS is mandatory (Wake Lock needs a secure context).
- No container ports published to the host; container joins the external Docker network `studioos-lan-edge` and Caddy proxies to it.
- All persistent data under one volume mounted at `/data` (SQLite file + images). Google tokens live in `/data/google-token.json`, NOT in the SQLite file, so snapshots uploaded to Drive never contain them.
- AI: Claude API, `ANTHROPIC_API_KEY`, model from `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`). AI output is only ever a draft; nothing is saved until the user taps Save. AI must never invent quantities, ingredients, or steps; unknowns are `null` and listed in `gaps`.
- Metric/UK units by default. Toggle state for Keep screen on remembered per device (localStorage).
- Google OAuth scope `drive.file` (+ `openid email` to show the account). Redirect URI `https://recipes.matchapman.dev/api/backup/google/callback`. OAuth app must be "In production" or refresh tokens expire after 7 days.
- Backup: nightly at 03:00 (`BACKUP_HOUR`, default 3), Drive folder "Recipes backup", keep last 14 snapshots, images uploaded incrementally by content hash.
- Banner on library page when: Google not connected, last backup failed, or no success in over 36 hours.
- Server-side URL fetch must refuse private, loopback, and link-local addresses.
- Secrets only via `.env`; never committed. Never push to a remote without being asked.

## Review Focus

1. Describe text with no quantities ("bit of wine") → quantity `null` plus an entry in `gaps`; nothing invented. (Task 7)
2. Import URL that is, or redirects to, a private/loopback address or a non-http scheme → rejected. (Task 8)
3. JSON-LD variants: `@graph` wrapper, `@type` as an array, `HowToSection` steps, ISO-8601 durations like `PT1H30M`, multiple JSON-LD blocks. (Task 8)
4. Wake lock: tab hidden then visible re-acquires; leaving the view releases; browser without the API shows a note. (Task 5)
5. Backup: Drive auth error → status `failed`; a partial upload failure never records success; a second run uploads no already-present images; retention trims to 14. (Task 9)

Also pinned in tasks: non-image or oversized upload rejected (Task 6).
